# FileNest 工程设计

## 数据流

1. Node 扫描用户选择的根目录，记录相对路径、大小、修改时间和 SHA-256。
2. 对摘要相同的候选文件逐字节比较，形成确认过的重复组。
3. MoonBit 核心验证扫描选择、规则和父目录占用事实，返回确定性的整理计划与统计摘要。
4. Node 适配层在服务端保存本次预览 ID，并把经过批准的计划交给 MoonBit 事务核心生成操作序列。
5. 用户批准当前预览后，执行层重新核对所有源文件指纹。
6. 所有源文件先进入本批次暂存目录，再放到最终位置；每一步都更新日志。
7. 撤销先验证全部相关文件，再暂存目标文件，最后恢复到原位置。

## 核心与适配层

MoonBit 核心不访问时钟、文件系统或网络，负责：

- 文件类型分类；
- 自定义规则的优先匹配；
- 数字感知的文件名排序；
- 有序批量命名规则；
- 跨平台路径和文件名诊断；
- 排除、冲突、自动编号和重复隔离计划。
- 大整数文件大小计算、扫描统计和重复文件保留建议；
- CSV、Markdown 与 JSON 报告生成；
- 快照规范化及新增、删除、修改、移动对比；
- `.fnrules` 词法解析、逐行诊断和配置生成；
- 配置与模板校验、事务操作构建、阶段转换和撤销调度。

Node 负责操作系统适配、内容摘要、逐字节比较、原子日志写入、硬链接移动和本地 HTTP 服务。恢复中的文件身份核验由 Node 执行，阶段判定和撤销顺序由 MoonBit 生成。浏览器不能直接访问任意文件，也不能提交任意文件操作；它只能执行服务端保存的当前预览。

## 操作状态机

批次状态：

```text
running ──→ completed
   │
   └──────→ interrupted

completed / interrupted ──→ undoing ──→ undone
                                  └────→ undo-failed
```

单文件状态：

```text
pending → staged → applying → done
                    │
done → undo-staging → restaging → restoring → restored
```

`applying`、`undo-staging` 和 `restoring` 会在实际文件操作前写入日志，用于识别日志更新与文件变化之间的中断。

## 不覆盖设计

- 用户路径必须相对于选定目录，拒绝绝对路径、`..` 和内部状态目录。
- 扫描和每次使用路径时都检查符号链接或目录联接。
- 执行前重新计算源文件的 SHA-256，并核对大小与修改时间。
- 创建目标使用排他的硬链接；目标存在时底层操作直接失败，不会替换目标。
- 新链接的内容验证成功后才移除旧链接。
- 预览期间未选中的文件和目录也会占用名称，不能被计划覆盖。

## 中断恢复

如果进程在“创建新链接”和“删除旧链接”之间退出，恢复时可能看到两个路径。FileNest 只有在设备号和 inode 都相同时，才把它们判断为同一文件的一次未完成移动。内容相同但彼此独立的文件不会被当成中断副本删除。

日志采用临时文件、文件同步和原子改名更新。当前实现没有跨平台目录同步，因此不能把它描述为突然断电下的完整事务系统。

## 本地 HTTP 边界

服务只监听 loopback，并验证：

- 精确的 `Host`；
- 同源 `Origin`；
- `Sec-Fetch-Site`；
- 进程启动时随机生成的会话令牌；
- JSON 请求类型和 2 MiB 请求大小上限。

静态文件使用固定白名单。Content Security Policy 禁止外部脚本、第三方嵌入和表单提交。工作文件不经过 HTTP 返回给浏览器，浏览器只获取名称、路径、大小、摘要和计划状态。

## 已知边界

- 操作要求源和目标位于同一支持硬链接的卷。
- 同目录操作由锁串行化；遗留锁只在对应进程不存在时回收。
- FileNest 防止普通的意外覆盖，但不是用来隔离本机恶意并发进程的安全沙箱。
- 恢复新增目录不会自动清理，避免误删后来写入的内容。

## 测试层次

- MoonBit 测试：排序性质、规则顺序、命名边界、确定性、排除、冲突、报告、精确大小计算、事务状态、分析、快照和规则文件。
- Node 文件测试：真实读写、目标占用、内容变化、名称交换、隔离、中断和恢复。
- HTTP 测试：扫描到撤销的完整流程、失效预览、跨站拒绝和报告导出。
- 浏览器验收：首屏、扫描、规则编辑、重复副本选择、执行确认和历史恢复。
